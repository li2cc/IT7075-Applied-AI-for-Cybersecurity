Getting Started with the Course Notebooks

Module 04: Retrieval-Augmented Generation (RAG) · Clone the repository, open the notebook, and install every package on Google Colab, Jetstream2, or your own computer.

Every notebook in this course lives in one GitHub repository. To run one you need three things: a copy of the repository, a place to run the notebook, and the Python packages it imports. This guide covers all three. It also covers the one check that prevents the most common problem: a notebook that cannot find its files.

2. Know the repository layout

The course repository is github.com/li2cc/IT7075-Applied-AI-for-Cybersecurity. It is public, and you can clone it (make your own copy) but not push to it. Your submission goes in your own private repository (step 7). After cloning you will have this:

IT7075/                                  <- the repository (your .env goes here)
├── requirements.txt                     <- every package for the whole course
├── .pip-constraints.txt                 <- version pins, applied automatically
├── 01_Introduction_to_AI/ ... 08_Cybersecurity_Orchestration/
└── 04_RAG/
    ├── requirements.txt                 <- this module's packages
    ├── code/
    │   ├── ssrf.txt
    │   └── cybersecurity_kb.md
    └── assignments/project/
        ├── MiniProject_RAG_Starter.ipynb     <- run it from this folder
        └── baseline_goldset.json

The notebook finds its files by relative paths, starting from the notebook's own folder. For example, ../../code/ssrf.txt means "go up two folders to 04_RAG, then into code". Keep this layout and run the notebook from its own folder, and every path works, whatever you call the top folder and wherever you put it.

Keep the folders as they are

Paths break when you move the notebook, rename a folder, or open the notebook on its own without the rest of the repository. Steps 3 and 5 make sure none of these happen.

3. Get the code and open the notebook

A. Google Colab

  1. Go to colab.research.google.com and choose File → New notebook. This blank notebook is only for the next command.
  2. Paste this into a cell and run it once. It saves a copy of the repository in your Google Drive, so your work is still there when Colab shuts down. Allow access to Drive when Colab asks.
from google.colab import drive
drive.mount("/content/drive")
!git clone https://github.com/li2cc/IT7075-Applied-AI-for-Cybersecurity.git /content/drive/MyDrive/IT7075
  1. In Google Drive, go to My Drive → IT7075 → 04_RAG → assignments → project, right-click MiniProject_RAG_Starter.ipynb, and choose Open with → Google Colaboratory.
  2. Add the setup cell from step 5 as the first cell, and run it.

Why not open the notebook straight from GitHub?

Colab's Open notebook → GitHub loads the notebook but none of the files next to it, and starts in /content instead of the notebook's folder. That combination is what causes the path errors. Colab also forgets installed packages whenever the session ends, so the setup cell reinstalls them and moves into the right folder every time you run it.

B. Jetstream2 VM

Open a terminal on your VM, either on the desktop (see the VM Access Guide) or with ssh exouser@<your-VM-IP>. Then run:

4. Install all the packages at once

Each module has a requirements.txt that lists its packages, and the one in the IT7075 folder includes them all. Install from these files, not package by package. They also hold the version limits the notebooks were tested with, so a new release that changes an API cannot break your notebook.

Jetstream2 and your own computer: the whole course, once

With your .venv active, in the IT7075 folder, run:

pip install --upgrade pip
# Jetstream2 only (see the box below):
pip install torch --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements.txt

That installs everything for the whole semester, so later modules need no more setup. It takes 10 to 15 minutes and about 7 GB of disk. When you git pull course updates, run pip install -r requirements.txt again in case the list changed.

Jetstream2: do not skip the torch line

The default PyTorch build needs a newer NVIDIA driver than the class VMs have. Without the cu121 line, PyTorch installs but cannot see the GPU (torch.cuda.is_available() returns False). On your own computer, leave that line out: the default build suits most computers. If yours has an NVIDIA GPU, pytorch.org gives the right command.

Google Colab: this module, every session

Colab already has most of these packages, and it forgets anything you add when the session ends. So install only this module's list, every session. The setup cell in step 5 does it for you, running the equivalent of:

!pip install -q -r /content/drive/MyDrive/IT7075/04_RAG/requirements.txt

Red messages from "pip's dependency resolver" about other Colab packages are normal. If Colab asks you to restart the session, do so, then run the setup cell again.

5. Add the setup cell

Paste this in as the first cell of the notebook (select the top cell, then Insert → Code cell above it) and run it every time you open the notebook. On Colab it mounts your Drive, installs the packages, moves into the notebook's folder, and reads your API key from Colab Secrets. On Jetstream2 or your own computer it reads your key from .env. In every environment, it then checks that the notebook can find its files.

# ---- Setup: run this cell first, every time you open the notebook ----
import os, sys, subprocess

# The three settings that change from module to module:
# 1. this module's package list, inside the repository
MODULE_REQS = "04_RAG/requirements.txt"
# 2. (Colab only) the Drive folder this notebook is in
COLAB_FOLDER = "/content/drive/MyDrive/IT7075/04_RAG/assignments/project"
# 3. files the notebook reads, as seen from its own folder
NEEDED = [
    "../../code/ssrf.txt",
    "../../code/cybersecurity_kb.md",
    "baseline_goldset.json",
]

REPO_URL = "https://github.com/li2cc/IT7075-Applied-AI-for-Cybersecurity.git"
REPO = "/content/drive/MyDrive/IT7075"  # Colab's copy of the repository

if "google.colab" in sys.modules:
    from google.colab import drive, userdata
    drive.mount("/content/drive")
    if not os.path.isdir(REPO):
        subprocess.run(["git", "clone", "-q", REPO_URL, REPO], check=True)
    subprocess.run([sys.executable, "-m", "pip", "install", "-q",
                    "-r", os.path.join(REPO, MODULE_REQS),
                    "-c", os.path.join(REPO, ".pip-constraints.txt")],
                   check=True)
    os.chdir(COLAB_FOLDER)
    try:
        os.environ["OPENAI_API_KEY"] = userdata.get("OPENAI_API_KEY")
    except Exception:
        print("No OPENAI_API_KEY in Colab Secrets (fine if not needed).")
else:
    # Jetstream2 or your own computer: packages are in .venv (step 4).
    # Read the API key from the .env file in your IT7075 folder, if any.
    try:
        from dotenv import load_dotenv, find_dotenv
        load_dotenv(find_dotenv(usecwd=True))
    except ImportError:
        pass

print("Working folder:", os.getcwd())
missing = [f for f in NEEDED if not os.path.exists(f)]
if missing:
    raise FileNotFoundError(f"Not found from this folder: {missing}. "
                            "See step 6 of the setup guide.")
print("All course files found. You are ready to go.")

It should end with All course files found. You are ready to go. If it raises FileNotFoundError, go to step 6.

API keys

Never type a key into a notebook cell: saved outputs and GitHub history keep it. On Colab, click the key icon in the left sidebar, add a secret named OPENAI_API_KEY, and turn on Notebook access. Elsewhere, put the line OPENAI_API_KEY=sk-... in a file named .env in the IT7075 folder. The repository's .gitignore keeps .env out of Git.

6. Check your paths

If the setup cell reports missing files, or a later cell raises FileNotFoundError, the notebook is running from the wrong folder. Look at the Working folder line the setup cell printed:

Working folder printedWhat it means
.../IT7075/04_RAG/assignments/projectThe folder is right, so a file is missing. Run git status in the IT7075 folder to see whether one was deleted or moved, or clone the repository again.
/contentColab, with a notebook opened from GitHub or uploaded on its own. Open it from Drive (step 3A) and run the setup cell.
Anywhere elseYou are running a moved or downloaded copy of the notebook. Open the one inside IT7075/04_RAG/assignments/project.

To see exactly what the notebook sees, run this in a cell:

import os
print(os.getcwd())
print(os.listdir("."))

7. Submit from your own private repository

The project brief asks for a private GitHub repository, with your instructor and the TA added as collaborators, that holds your work in a rag_project/ folder. Do not fork the course repository: a fork of a public repository is public, so everyone could see your work.

  1. On GitHub, click New repository, choose Private, and tick Add a README. Then open Settings → Collaborators and add your instructor and the TA.
  2. In that repository, make a rag_project/ folder. Copy your finished notebook into it as rag_notebook.ipynb, and copy the three practice files next to it: ssrf.txt, cybersecurity_kb.md and baseline_goldset.json. Add your my_kb/ folder, goldset.json, results.csv and your chart.
  3. The practice files now sit beside the notebook instead of two folders up, so change two lines. In Part 1, replace the COURSE_KB = ... line with the one below. In the setup cell, set NEEDED to the three file names, and on Colab point COLAB_FOLDER at your rag_project folder in Drive. baseline_goldset.json needs no change: the notebook already looks for it beside itself.
COURSE_KB = ["ssrf.txt", "cybersecurity_kb.md"]
# in the setup cell:
NEEDED = ["ssrf.txt", "cybersecurity_kb.md", "baseline_goldset.json"]
  1. Choose Restart and run all, check that every cell ran, save the notebook, and commit and push it with its outputs. From Colab, the easiest way is File → Download → Download .ipynb, then Add file → Upload files on your repository's GitHub page.

8. When something goes wrong

You seeDo this
ModuleNotFoundError: No module named 'chromadb'The packages are not in the Python the notebook is using. On Colab, run the setup cell (each new session starts empty). In VS Code or Jupyter, choose the .venv kernel, or activate .venv before starting jupyter lab.
FileNotFoundError: ... ssrf.txtThe notebook is in the wrong folder. See step 6.
NameError: name '____' is not definedNot a setup problem. A TODO blank is still waiting for your code.
fatal: destination path 'IT7075' already existsYou have already cloned it. To get course updates, cd IT7075 and then git pull.
git pull says your local changes would be overwrittenYou edited a file that the instructor has since updated. Run git stash, then git pull, then git stash pop to keep both versions.
ensurepip is not available when creating .venvOn Jetstream2 or Ubuntu, run sudo apt install -y python3-venv, then create the .venv again.
torch.cuda.is_available() is False on Jetstream2Run the cu121 torch command from step 4 again.
No space left on devicedf -h ~ shows how much space is free, and pip cache purge clears pip's download cache.
Windows: running scripts is disabled on this systemRun Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, then activate .venv again.
